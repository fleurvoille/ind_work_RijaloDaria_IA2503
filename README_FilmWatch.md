# FilmWatch

FilmWatch — серверное веб-приложение на PHP для просмотра каталога фильмов. Данные хранятся в PostgreSQL. Интерфейс выполнен в минималистичном тёмном стиле.

## Описание работы

Цель проекта — разработать веб-приложение с динамическим каталогом, регистрацией и авторизацией пользователей, личными функциями и административным управлением записями.

## Технологии

- PHP
- PostgreSQL
- PDO для подключения к базе данных
- Docker для запуска PostgreSQL
- HTML и CSS
- PHP Sessions для авторизации

## Запуск проекта

1. Установите PHP с поддержкой PDO PostgreSQL и Docker Desktop.
2. Запустите контейнер PostgreSQL с базой данных `filmwatch`.
3. Создайте таблицы из раздела «Структура базы данных».
4. В файле `config/database.php` укажите параметры подключения к вашей базе данных.
5. В корневой папке проекта выполните:

   ```bash
   php -S localhost:8000
   ```

6. Откройте в браузере: <http://localhost:8000>

> Если база данных запускается через собственный Docker Compose, используйте параметры подключения, заданные в вашем compose-файле. Не публикуйте пароль базы данных в открытом репозитории.

## Содержание и функциональные возможности

- Главная страница с динамическим выводом фильмов из базы данных.
- Каталог фильмов.
- Поиск и фильтрация фильмов.
- Страница с подробной информацией о фильме.
- Регистрация и авторизация пользователей.
- Хеширование паролей.
- Профиль пользователя.
- Добавление фильмов в избранное и удаление из избранного.
- Административная панель.
- Добавление, редактирование и удаление фильмов.
- Просмотр списка пользователей и удаление других пользователей администратором.

## Сценарии использования

### Посетитель
1. Открывает главную страницу.
2. Переходит в каталог и ищет нужный фильм.
3. Открывает страницу фильма.
4. Регистрируется или входит, чтобы использовать персональные функции.

### Зарегистрированный пользователь
1. Входит в аккаунт.
2. Открывает профиль.
3. Добавляет фильмы в избранное.
4. Просматривает и редактирует список избранного.

### Администратор
1. Входит в аккаунт с ролью `admin`.
2. Открывает `/admin/index.php`.
3. Добавляет, редактирует или удаляет фильмы.
4. Открывает раздел управления пользователями.

## Структура базы данных

База данных: `filmwatch`.

### `users`

| Поле | Тип / назначение |
|---|---|
| `id` | `SERIAL PRIMARY KEY` |
| `username` | `VARCHAR(100) NOT NULL` |
| `email` | `VARCHAR(150) UNIQUE NOT NULL` |
| `password` | `VARCHAR(255) NOT NULL` — хеш пароля |
| `role` | `VARCHAR(20)`, по умолчанию `user` |

### `movies`

| Поле | Тип / назначение |
|---|---|
| `id` | `SERIAL PRIMARY KEY` |
| `title` | `VARCHAR(200) NOT NULL` |
| `description` | `TEXT NOT NULL` |
| `year` | `INTEGER NOT NULL` |
| `genre` | `VARCHAR(100) NOT NULL` |
| `rating` | `DECIMAL(3,1)`, по умолчанию `0` |
| `poster` | `VARCHAR(255)` |
| `trailer` | `VARCHAR(255)` |

### `favorites`

| Поле | Тип / назначение |
|---|---|
| `id` | `SERIAL PRIMARY KEY` |
| `user_id` | внешний ключ на `users(id)`, `ON DELETE CASCADE` |
| `movie_id` | внешний ключ на `movies(id)`, `ON DELETE CASCADE` |
| Ограничение | `UNIQUE(user_id, movie_id)` — не допускает дубликаты |

Связи: один пользователь может иметь много записей избранного; один фильм может находиться в избранном у многих пользователей. Таблица `favorites` связывает `users` и `movies`.

## Безопасность

- Пароли сохраняются в виде хешей с помощью `password_hash()`.
- Проверка пароля выполняется через `password_verify()`.
- Для SQL-запросов с пользовательскими значениями используются подготовленные запросы PDO.
- Для вывода пользовательских данных применяется `htmlspecialchars()`.
- Доступ к защищённым страницам проверяется через сессию.
- Доступ к административным страницам ограничивается ролью `admin`.
- Удаление пользователя не позволяет удалить текущий аккаунт администратора через страницу управления пользователями.

## Ответы на контрольные вопросы

**1. Для чего используется PHP?**  
PHP выполняет серверную логику: обрабатывает запросы и формы, взаимодействует с базой данных и формирует HTML.

**2. Что такое PDO?**  
PDO — расширение PHP для работы с базами данных через единый интерфейс. Оно поддерживает подготовленные запросы.

**3. Для чего нужны подготовленные запросы?**  
Они отделяют SQL-команду от пользовательских значений и помогают предотвращать SQL-инъекции.

**4. Что такое сессия PHP?**  
Сессия хранит данные пользователя между запросами, например идентификатор и роль после входа.

**5. Почему пароли нужно хешировать?**  
Хеширование не позволяет хранить пароль в открытом виде. Для этого используются `password_hash()` и `password_verify()`.

**6. Чем отличаются аутентификация и авторизация?**  
Аутентификация подтверждает личность пользователя, а авторизация определяет его права доступа.

**7. Что такое SQL-инъекция?**  
Это внедрение постороннего SQL-кода через пользовательский ввод. Защита в проекте — подготовленные запросы PDO.

**8. Для чего применяется `htmlspecialchars()`?**  
Функция преобразует специальные HTML-символы при выводе данных и помогает предотвращать XSS.
